📋 1. 项目概览

Deskemoji 是一个基于 Rust 开发的 Windows 原生桌面小程序（Desktop Widget）。它在桌面右下角显示一个动态 Emoji 表情浮窗，能够根据系统状态、时间和用户交互实时切换表情，提供一种生动的桌面陪伴体验。

4.2 核心状态机（main.rs）

程序采用 winit 事件循环驱动，核心状态包括：

  • Idle 状态：表情执行轻微呼吸缩放动画
  • Gaze 状态：根据鼠标相对位置切换 9 方向表情变体
  • Bounce 状态：左键点击触发弹跳物理动画
  • Transition 状态：表情切换时的 180ms 淡入淡出过渡
  • Closed-eye 响应：快速移动鼠标时触发闭眼躲避效果

4.3 渲染器架构（renderer.rs）

renderer.rs 是整个项目技术含量最高的模块，实现了一套自研的 2D 软件渲染管线：

渲染特性清单：
  • 双线性采样（Bilinear Sampling）
  • 预乘 Alpha（Premultiplied Alpha）混合
  • 基于 Catmull-Rom 的高质量图像缩放
  • 透明边缘颜色保留，避免黑边
  • 圆角矩形 + 尾巴气泡 UI 绘制
  • 位图字体数字渲染，用于状态百分比显示
  • 状态强调动画（不同表情有不同的呼吸/强调幅度）

4.4 配置系统（config.rs）

运行时配置以 JSON 形式保存在 config.json 中（与 exe 同级）：

{
  "auto_mode": true,
  "startup": false,
  "update_interval_secs": 2,
  "cpu_threshold": 80.0,
  "memory_threshold": 90.0,
  "idle_threshold_secs": 300,
  "opacity": 1.0,
  "window_size": 120
}

配置读写使用了较多的 .ok() 忽略错误，损坏时静默回退到默认值。容错性较好，但用户无感知。

✨ 5. 核心功能解析

5.1 情绪感知系统（Auto Mode）

每 update_interval_secs 秒检测一次系统状态，自动切换表情：

触发条件表情含义
CPU > 80%🥵 hotCPU 过热警告
内存 > 90%🤯 mindblown内存压力爆表
空闲时间 > 300 秒😴 sleepy用户长时间未操作
22:00 ~ 05:00😌 goodnight深夜时段
10:00 ~ 17:00🤔 thinking工作时段
其他情况🙂 happy默认开心状态

5.2 视线跟随（Gaze Tracking）

项目最具特色的交互设计之一。每个基础表情（除 sleepy/goodnight 外）配有 9 个方向变体：

  • Center — 正视前方
  • Up / Down / Left / Right — 上下左右
  • UL / UR / DL / DR — 四个对角线方向

程序根据鼠标相对于窗口中心的偏移量，实时选择最合适的变体，实现 Emoji "盯着鼠标看" 的生动效果。

5.3 状态气泡（Status Bubble）

当系统处于 Hot 或 Mindblown 状态时，表情上方会浮现一个圆角气泡，实时显示 CPU 或内存的使用率百分比。气泡支持尾巴锚点定位，始终指向 Emoji 中心。

5.4 系统托盘与开机启动

  • 托盘右键菜单支持手动锁定表情、切换自动模式、查看设置、退出程序
  • 通过读写 Windows 注册表 HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run 实现开机自启
  • 设置窗口目前使用 MessageBoxW 显示当前配置JSON，尚未实现可视化设置 UI

6.1 产品定位与价值主张

Deskemoji 的核心价值主张是"系统状态的情绪化可视化 + 桌面陪伴"。它不是传统的系统监控工具，而是将冰冷的性能数据转化为有温度的表情反馈。

定位升级建议：从"Windows 系统监控挂件"升级为"你的桌面情绪伴侣"（Desktop Emotional Companion）。产品重心应从"工具属性"向"陪伴属性"迁移，因为工具可以被替代，但情感连接能产生粘性。

6.2 目标用户画像（Persona）

核心用户：桌面美化爱好者

  • 18-28 岁，Z 世代为主
  • 活跃于小红书、抖音、Twitter/X、B站
  • 热衷于 desk setup、桌面整理、个性化美化
  • 愿意为"情绪价值"和"颜值"付费
  • 传播力强，喜欢截图分享

次要用户：轻度效率/监控需求者

  • 开发者、设计师、远程工作者
  • 不喜欢传统任务管理器的复杂界面
  • 希望以轻松方式了解电脑状态
  • 长时间面对屏幕，需要桌面陪伴感

6.7 产品风险与壁垒

⚠️ 风险点

  • Windows 独占：天花板有限，macOS 用户无法触达
  • 新鲜感曲线：桌宠类产品容易因"看腻了"而被卸载
  • 安全软件误报：注册表操作、常驻后台可能被误杀
  • 壁垒不高：核心功能较易被竞品模仿
  • 打扰风险：全屏时不自动隐藏可能导致用户流失

🛡️ 护城河构建

  • 情感连接：通过 AI 人格化建立用户与 Emoji 的独特关系
  • 内容生态：先发优势建立皮肤市场和创作者社区
  • 数据积累：长期系统使用数据生成个性化周报/洞察
  • 跨平台网络效应：账号体系实现多设备状态同步
  • 社交资产：用户积累的成就、皮肤、关系具有迁移成本

📊 7. 代码质量评估

8.0

技术综合评分 / 10 分

7.1 优点

  • 模块化清晰：配置、监控、渲染、资源、菜单各司其职，模块边界明确
  • 自研渲染管线：在没有 Skia/wgpu 的情况下实现了高质量的 2D 软件渲染
  • 测试覆盖核心逻辑：渲染数学、资源加载、气泡布局、视线方向均有测试验证
  • Windows 原生体验：Win32 API 实现右键菜单和注册表自启，贴近原生应用
  • 工程意识强：Release 配置积极优化体积，.gitignore 合理

7.2 可改进点

  • Magic Numbers 较多：大量动画参数、阈值、坐标硬编码在代码中，建议抽取为常量或配置项
  • menu.rs 存在死代码：该模块构建的 tray-icon 菜单在 main.rs 中未被实际使用，主程序使用 Win32 API 自建菜单
  • renderer.rs 体积过大：1156 行承载渲染器、动画数学、UI 绘制、位图字体等多重职责，建议拆分子模块
  • 配置错误处理偏静默：load/save 大量使用 .ok() 忽略错误，用户无法感知配置异常
  • unsafe 代码注释不足：settings.rs 中的 RegSetValueExW 数据转换可补充安全说明

10.2 产品改进建议（按影响排序）

立刻
游戏/全屏勿扰模式

检测用户进入全屏游戏或视频时，自动降低透明度或隐藏到托盘。这是防止电竞/影音用户卸载的生死线功能。

立刻
新用户 Onboarding 引导

首次启动时通过简短动画演示核心交互："移动鼠标看看它的眼睛"、"点击它会弹跳"、"快速晃鼠标它会闭眼"。当前很多精妙设计用户根本发现不了。

短期
截图分享卡片（病毒传播核心）

右键菜单增加"生成今日状态卡片"，输出精美图片（Emoji + CPU/内存数据 + 励志/幽默文案），适配社交媒体传播。底部带品牌水印和官网/Steam 链接。

短期
成就与彩蛋系统

增加趣味成就解锁机制：连续开机 7 天获得隐藏表情、深夜使用触发关心对话、CPU 爆表时触发特殊动画。用游戏化设计对抗新鲜感衰退。

短期
社交状态同步

将当前 Emoji 状态同步到 Discord Rich Presence、QQ 状态、微信状态。让用户的"桌面心情"成为社交身份的一部分。

📝 11. 总结

技术层面

Deskemoji 是一个完成度较高的个人/小型桌面工具项目。它巧妙地利用了 Rust 的系统级能力和纯软件渲染技术，在 Windows 平台上实现了一个体积小巧、交互生动的桌面 Emoji 挂件。自研的 2D 渲染管线保证了精致视觉效果，9 方向视线跟随赋予了 Emoji 灵动的生命力，系统状态感知让它不仅仅是一个装饰品，而是一个能"表达情绪"的桌面伴侣。核心逻辑的测试覆盖也体现了开发者对质量的关注。

产品层面

从产品视角看，Deskemoji 已经具备了成为一个小而美独立产品的所有潜质。它的核心价值不在于系统监控的技术准确性，而在于将冰冷的数字转化为有温度的情绪反馈。这种"情绪价值 + 实用价值"的组合，在当下的桌面美化市场和 AI 陪伴热潮中非常有竞争力。

但产品目前仍处于功能驱动的阶段，尚未完成向体验驱动和增长驱动的跃迁。最紧迫的产品任务是：

  1. 解决打扰问题（游戏勿扰模式，降低用户流失）
  2. 增加病毒传播机制（截图分享卡片，实现低成本获客）
  3. 建立情感连接（AI 人格化、成就系统，对抗新鲜感衰退）
总体评价：这是一个兼具技术深度、产品趣味和商业潜力的优秀项目。代码功底扎实，产品切入点精准，如果能补齐增长和商业化环节，有潜力从个人项目进化为一款受全球用户喜爱的桌面情绪伴侣。
